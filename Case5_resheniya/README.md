# Кейс-задача № 5 — Способы решения выявленных проблем

## Задание

На основе проведённого анализа в кейс-задаче № 4 предложите способы решения выявленных проблем в ходе выполнения кейс-задачи № 3.

## Ответ

По результатам анализа чат-бота (кейс № 4) я выявил следующие проблемы и предлагаю способы их решения.

### 1. Ошибки при неоднозначных словах

**Проблема.** Одно слово может относиться к разным темам. Фразу «Во сколько работает университет» бот относит к стоимости из-за слова «сколько», а не к расписанию. Точность распознавания 97,5 %, все ошибки такого типа.

**Решение.** Добавить в списки ключевых слов устойчивые словосочетания. Они весят больше одного слова, поэтому побеждают в подсчёте:

- расписание: «во сколько», «до скольки», «с какого времени»;
- стоимость: «сколько стоит», «какая цена», «сколько платить».

После добавления фразы «Во сколько работает университет» будет относиться к расписанию, а «Сколько стоит обучение» к стоимости. Новые фразы необходимо добавить в тесты `test_bot.py`, чтобы точность проверялась автоматически.

### 2. Опечатки в вопросах

**Проблема.** Бот сравнивает слова точно, поэтому «докумены» или «расписнаие» он не распознает.

**Решение.** Перед сравнением сверять слово пользователя со списком ключевых слов по степени схожести. В стандартной библиотеке Python для этого есть `difflib.get_close_matches`:

```python
import difflib

def fix_typo(word, vocabulary):
    match = difflib.get_close_matches(word, vocabulary, n=1, cutoff=0.8)
    return match[0] if match else word
```

Порог 0,8 позволяет исправлять одну-две ошибки в слове и не менять правильные слова. Дополнительные пакеты не нужны.

### 3. Бот не помнит контекст диалога

**Проблема.** Каждый вопрос обрабатывается отдельно. На «А завтра?» или «А в Казани?» после вопроса о погоде бот отвечает «не понял».

**Решение.** Хранить состояние диалога: последнюю тему и город.

```python
context = {"intent": None, "city": None}
```

Если вопрос короткий и своих ключевых слов не содержит, бот берёт тему из `context["intent"]`, а недостающие данные (город, день) из вопроса или из памяти. Кроме того, при низкой уверенности (ничья между темами) бот задаёт уточняющий вопрос: «Вы спрашиваете про стоимость или про расписание?».

### 4. Ограниченный список городов для погоды

**Проблема.** Погоду бот показывает только для 16 городов из словаря `CITIES`. Для остальных городов он отвечает температурой Москвы, что вводит в заблуждение.

**Решение.** Если город назван (слово после предлога «в»), но его нет в списке, передавать это название сервису напрямую, так как wttr.in находит города по названию. Если сервис не нашёл город (код ответа 404 или 500), бот честно сообщает: «Не нашёл такой город, уточните название». Вопрос без указания города по-прежнему относится к Москве. Список `CITIES` пополнять на основе журнала вопросов (см. п. 9).

### 5. Зависимость от одного сервиса погоды

**Проблема.** Если wttr.in работает медленно или недоступен, бот не может ответить о погоде. Возможны также задержки: сервис бесплатный и без гарантий работы.

**Решение.** Три уровня защиты:

1. **Резервный источник.** Подключить второй бесплатный сервис погоды и переключаться на него при ошибке основного (в `web_sources.py` это отдельная функция с тем же интерфейсом).
2. **Долгий кэш.** Хранить последний успешный ответ по каждому городу и при сбое показывать его с пометкой: «Данные на 14:30, сервис сейчас недоступен».
3. **Ограничение ожидания.** Сократить таймаут запроса с 8 до 3–4 секунд, чтобы пользователь не ждал ответа слишком долго.

### 6. Бот не понимает синонимы и смысл фразы

**Проблема.** Бот работает по ключевым словам. Вопрос «Как мне добраться до вас?» остаётся без ответа, потому что в нём нет слов из списка («адрес», «где находитесь»), хотя смысл тот же.

**Решение.** Использовать двухуровневую схему:

1. Типовые вопросы обрабатывать правилами, как сейчас: это быстро, бесплатно и предсказуемо.
2. Вопросы, на которые правила не нашли ответ, передавать языковой модели через API (например, YandexGPT или GigaChat). В запрос включить проверенную информацию об университете (справочный файл), чтобы модель отвечала только по ней и не выдумывала цены и сроки.

Первый уровень остаётся основным, поэтому скорость и стоимость ответов на типовые вопросы не изменятся. Ключ доступа к API хранить в переменной окружения, а не в коде.

### 7. Неудобный консольный интерфейс

**Проблема.** С ботом можно работать только из командной строки. Для абитуриентов и студентов это неудобно.

**Решение.** Подключить бота к Telegram. Функция `reply(text)` уже принимает текст и возвращает ответ, поэтому для интеграции достаточно обработчика сообщений (библиотека `python-telegram-bot` или `aiogram`), который вызывает `reply()`. Для частых тем добавить кнопки быстрых ответов: «Документы», «Формы обучения», «Стоимость», «Контакты», «Погода».

### 8. Ответы зашиты в код

**Проблема.** Тексты ответов (телефоны, режим работы, перечень документов) хранятся в `bot.py`. Чтобы изменить телефон или график, нужно править программу.

**Решение.** Вынести ключевые слова и ответы в отдельный файл `answers.json` и загружать его при запуске:

```json
{"contacts": {"keywords": ["телефон", "адрес"], "answer": "Телефоны: ..."}}
```

Тогда сотрудник университета сможет обновить справочную информацию без изменения кода. Для актуальных данных (цены, приём) добавить ссылку на страницу сайта университета.

### 9. Нет данных для улучшения бота

**Проблема.** Неизвестно, какие вопросы задают пользователи и на какие бот не смог ответить.

**Решение.** Записывать в журнал (`log.csv`) время, вопрос, определённую тему и признак «не понял». Раз в неделю просматривать вопросы без ответа, добавлять по ним ключевые слова и новые темы, а из повторяющихся вопросов формировать новые тесты. Это позволит регулярно повышать точность распознавания на реальных запросах, а не только на тестовых фразах.

| Этап | Улучшение | Эффект |

| 2 | Контекст диалога (п. 3), новые города (п. 4) | Естественный диалог, отсутствие неверных ответов о погоде |
