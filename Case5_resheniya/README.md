# Кейс-задача № 5 — Способы решения выявленных проблем

## Задание

На основе проведённого анализа в кейс-задаче № 4 предложите способы решения выявленных проблем в ходе выполнения кейс-задачи № 3.

## Ответ

1. **Неоднозначные слова** («сколько» и т.п.). Часть проблемы уже решена: введены веса и словосочетания («сколько градусов»). Остаётся добавить «во сколько», «сколько стоит» и учитывать порядок слов.
2. **Опечатки.** Нечёткое сравнение строк (расстояние Левенштейна из `difflib` в стандартной библиотеке, без новых пакетов).
3. **Нет контекста и уточнений.** Хранить состояние диалога (последняя тема и город), чтобы понимать «а завтра?», «а в Казани?»; при низкой уверенности уточнять («Вы про стоимость или расписание?»).
4. **Ограниченный список городов.** Пробовать название города из вопроса напрямую в запросе к сервису, а при ответе «город не найден» сообщать об этом пользователю; список `CITIES` расширять по частоте вопросов.
5. **Зависимость от одного сервиса погоды.** Добавить запасной источник (второй сервис) и переключаться на него при сбое основного; сохранять последний удачный ответ в кэш на длительное время и показывать его с пометкой о времени получения.
6. **Нет понимания синонимов.** Лемматизация (`pymorphy3`), затем эмбеддинги (`sentence-transformers`) или подключение языковой модели через API для неизвестных вопросов (гибридная схема: правила для типовых, модель для сложных).
7. **Неудобный интерфейс.** Подключить бота к Telegram (`aiogram`, `python-telegram-bot`) или веб-странице, добавить кнопки быстрых ответов.
8. **Устаревающие ответы.** Вынести ответы во внешний JSON или БД или связать с сайтом университета, чтобы обновлять без правки кода.
9. **Нет аналитики.** Логировать вопросы без ответа и по ним пополнять базу ключевых слов.
